# Cartly Smart Trolley — Customer App

React 18 + Vite app that mirrors a real shopping session on the Cartly trolley
(Raspberry Pi + FastAPI). It is a **display and checkout client**: the RFID card, camera
following and barcode scanner all live on the trolley; this app only reads their results
from the backend.

```
RFID scan at trolley → session starts → app switches to the live session automatically
→ barcode scans fill the cart → rental timer runs from the backend's started_at
→ checkout (real POST /api/checkout) → bill returned by the backend
```

No payment is integrated in this version, and nothing in the app simulates RFID, scans,
hardware, or a connection. If the backend is unreachable the app says so.

## Setup

Requires **Node 22+** (needed by Capacitor 8).

```bash
npm install
cp .env.example .env          # then edit the address if needed
npm run dev                   # http://localhost:5173  (also reachable on your LAN)
npm run build                 # production bundle in dist/
npm test                      # unit tests for billing, time parsing, API adapters and client
```

### Pointing the app at the Raspberry Pi

The address comes from `VITE_API_BASE_URL` in `.env`. Set it to the Raspberry Pi's current
LAN address before starting the app or building the Android package:

```
VITE_API_BASE_URL=http://<pi-address>:8000
```

The Pi's IP changes when it joins a different network or its DHCP lease changes. When that
happens, edit `.env` and rebuild (`npm run build`, or `npm run android:sync` for the APK).
The value is baked in at build time. A DHCP reservation for the Pi on your router avoids
repeating this. The phone must be on the same Wi-Fi network as the Pi.

Optional `VITE_NAIVE_TIMESTAMPS=utc|local` controls how timestamps without a time-zone
suffix are read (see `BACKEND_NOTES.md`).

### CORS

The FastAPI server must allow the origins the app is served from — an explicit list, not
`*` with credentials:

| Where the app runs | Origin to allow |
|---|---|
| `npm run dev` | `http://localhost:5173` (and `http://<laptop-ip>:5173` if used from a phone) |
| Android APK (Capacitor, this config) | `http://localhost` |

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173", "http://localhost"],
    allow_methods=["GET", "POST"],
    allow_headers=["*"],
    expose_headers=["Date"],   # lets the app detect a phone/Pi clock difference
)
```

## Android APK (Capacitor)

Prerequisites: Node 22+, JDK 21, Android Studio (Otter 2025.2.1 or newer) with an Android SDK.

```bash
npm install
cp .env.example .env                 # set VITE_API_BASE_URL first
npm run build                        # produces dist/
npm run android:init                 # one time: creates android/ and restricts cleartext HTTP to the Pi host
npm run android:open                 # opens the project in Android Studio -> Run, or:
npm run android:debug-apk            # builds android/app/build/outputs/apk/debug/app-debug.apk
```

After any change to the web code or `.env`: `npm run android:sync`. The `android:debug-apk`
script selects `gradlew.bat` on Windows and `./gradlew` on macOS/Linux.

Package ID: `com.cartly.smarttrolley` (`capacitor.config.json`).

**Network access.** The Pi is plain HTTP on a LAN. `scripts/configure-android.mjs` writes an
Android network-security config that permits cleartext **only to the host in
`VITE_API_BASE_URL`**; all other traffic stays HTTPS-only. If the Pi's IP changes, update
`.env` and re-run `npm run android:sync` (it regenerates that file). The WebView origin is
`http://localhost`, so the backend CORS list must include it (above).

The `android/` folder is generated by the Capacitor CLI and is not included in this
project; it is created by `npm run android:init`.

## Project structure

```
src/
  config.js                 base URL, polling intervals, billing constants
  api/client.js             the only place that calls fetch (timeout, errors, JSON)
  api/adapters.js           normalises backend responses; never invents values
  api/sessionApi.js         health, trolley status, active session, checkout
  api/cartApi.js            cart + latest scan (read-only)
  hooks/usePoller.js        sequential polling, no overlap, stale-response guard, pauses when hidden
  hooks/useBackendHealth.js / useActiveSession.js / useCart.js / useTrolleyStatus.js / useRental.js / useNow.js
  utils/billing.js          rental rule: max(1, ceil(elapsed/1800)) * 20
  utils/dateTime.js, format.js, finalBill.js
  components/               Header, ConnectionStatus, RentalTimer, SessionStatus, HardwareStatus,
                            CartItem, CartSummary, Banner, StateMessage
  pages/                    HomePage (loading / unreachable / waiting for RFID), ActiveSessionPage,
                            CheckoutPage, SessionCompletePage
tests/                      node:test unit tests
scripts/configure-android.mjs
```

## Behaviour notes

- **Polling:** health every 7 s (4 s while down), session every 1.5 s (4 s after repeated
  failures), cart and latest scan every 1.5 s while a session is active, trolley hardware
  status every 5 s. Requests never overlap, are cancelled on unmount, and older responses
  cannot overwrite newer state. Polling pauses while the app is in the background and
  refreshes immediately when it returns.
- **Timer and rental:** computed from the backend `started_at`, so reloads and network drops
  do not reset it. The charge is shown as *Confirmed by trolley* only when the backend's
  `usage_fee` agrees with the pricing rule; otherwise it is labelled *Estimated*.
- **Checkout** is only ever sent when the customer taps *Confirm checkout*. The live OpenAPI
  declares no request body, so the app sends an empty POST. Duplicate taps are blocked, failures
  keep the cart visible, and a session that vanishes is never checked out automatically.
- The top status describes FastAPI availability. The current backend says its `connected` field
  means the Raspberry Pi API is reachable; it does not establish that trolley hardware is online.
- **Product data** comes only from `GET /api/cart`. The app never calls `POST /api/scans` or
  `POST /api/cart/items`.
